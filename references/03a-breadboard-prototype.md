# 03a. 面包板原型验证（Breadboard Prototype）

全流程的环节 03a（可选但**强烈建议**，在 01 选型之后、03b 原理图之前）。先用**现成开发板 + 成品模块**在面包板上把 MVP 电路跑通，再决定要不要自画 PCB。对零基础者，这是全流程最省钱的一环：一次画错（天线净空、LDO 压差、去耦、USB-C 的 CC 下拉）打样回来就是废板 + 两周等待，而面包板验证的成本是几十块和一下午。输入：选型结论 + `docs/product-contract.md`；输出：一块在面包板上跑通的 MVP + 一张「原型 → 原理图迁移清单」。

## 目标与通过标准

- 目标：把产品合同的每个核心功能，用开发板 + 成品模块在面包板上各验证一遍，记录接线与功耗粗测，把「验证过的方案」交给 03b 画原理图。
- 通过标准：
  - 开发板能烧录并运行固件（回到 08 的「烧录授权门禁」流程）。
  - 每个核心外设（按键/LED/麦克风/功放/传感器/灯带）逐个接线、逐个点亮/出声/读到数据，并记录对应 GPIO。
  - 完成功耗粗测：万用表串电流或用 USB 电流表读峰值，核对 01 环节功耗预算的峰值电流数字。
  - 记录「哪些外设接线和预想不同」（这是 03b 原理图最重要的输入）。
  - 明确结论：继续自画板（进 03b/04/05）或改方案/换外设。

## 可复制操作与命令

本环节以接线与调试为主。命令用于固件验证与记录。

### 1. 接线要点表（面包板 MVP 常用外设）

| 外设 | 开发板接口 | 面包板接法 | 备注 |
| --- | --- | --- | --- |
| 按键 | GPIO 输入 | 一端接 GPIO，一端接 GND；代码开内部上拉或外接 10kΩ 上拉 | 按下=低电平；与 07 固件 20ms 消抖对齐 |
| LED | GPIO 输出 | 阳极串 220–330Ω 接 GPIO，阴极接 GND | 别直连 3.3V |
| WS2812 灯带 | GPIO 输出 | DIN 串 330–470Ω 接 GPIO，VCC=5V，GND 共地 | 5V 灯带需要外部 5V 电源 |
| INMP441 麦克风 | I2S | SCK/WS/SD 各接一个 GPIO，VDD=3.3V，L/R 接 GND | 接线顺序错=采到噪声/无数据 |
| MAX98357A 功放 | I2S | DIN/BCLK/LRC 接 GPIO，Vin=5V，喇叭接 OUT+/- | 喇叭 4–8Ω，先小音量 |
| I2C 传感器 | I2C | SDA/SCL 接 GPIO，4.7kΩ 上拉到 3.3V | 用 `i2c scan` 先确认地址 |
| 蜂鸣器 | GPIO 输出 | 三极管驱动或模块，别直接推 | 有源/无源区别见 03 |

### 2. 固件验证脚本（ESP-IDF 快速点亮/打印）

用最小工程先验证「开发板 + 单个外设」链路，逐个外设重复：

```c
// main.c 最小验证：按键 + LED（改外设时只改这里）
#include "driver/gpio.h"
#include "esp_log.h"

#define LED_PIN  GPIO_NUM_8
#define KEY_PIN  GPIO_NUM_0

void app_main(void) {
    gpio_set_direction(LED_PIN, GPIO_MODE_OUTPUT);
    gpio_set_direction(KEY_PIN, GPIO_MODE_INPUT);
    gpio_set_pull_mode(KEY_PIN, GPIO_PULLUP_ONLY);
    int n = 0;
    while (1) {
        int pressed = gpio_get_level(KEY_PIN) == 0;
        gpio_set_level(LED_PIN, pressed ? 1 : 0);
        if (n % 100 == 0) ESP_LOGI("proto", "key=%d led=%d", pressed, gpio_get_level(LED_PIN));
        n++;
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}
```

### 3. 功耗粗测（核对 01 功耗预算）

- 方法 A（最简单）：USB 电流表/功率计串在开发板电源输入，记录待机电流与峰值（开 WiFi、播放声音时的读数）。
- 方法 B：万用表电流档串进 5V 线（红笔在正极侧），短时间测量；测完立刻恢复直连。
- 记录：`docs/prototype-power-log.md`——稳态电流、峰值电流、对应工况。回填到 01 的功耗预算数字（若实测偏差 >30%，更新选型结论）。

### 4. 原型 → 原理图迁移清单（03b 的输入）

面包板验证通过后，把下面这张表填好，交给 03b 画原理图时逐行核对：

| 外设 | 面包板用 GPIO | 实测电压域 | 实测电流 | 接线注意事项（与预想不同处） |
| --- | --- | --- | --- | --- |
| 按键 | GPIO0 | 3.3V | — | 需要外部上拉吗？ |
| LED | GPIO8 | 3.3V | <20mA | 串 330Ω |
| WS2812 | GPIO9 | 5V | 实测峰值 | 数据线串 330Ω，5V 独立供电 |
| 麦克风 | GPIO11/12/13 | 3.3V | 实测 | I2S 顺序核对 |
| 功放 | GPIO14/15/16 | 5V | 实测 | 喇叭 4Ω |
| 传感器 | GPIO17(SDA)/18(SCL) | 3.3V | 实测 | I2C 上拉 4.7kΩ |

> 迁移清单是 03b 原理图「防幻觉检查」的证据来源之一：每个外设的 GPIO、电压域、电流都来自**实测记录**，不是 AI 猜测。

## 常见坑

1. **现象**：面包板验证都通过了，画完板打样回来却不工作。**原因**：原型用的是成品模块（模块自带稳压/电平转换/去耦），自画板时这些「模块内藏」的东西全没了。**解决**：迁移清单里逐项标注「模块内置 vs 需自画板补」，03b 原理图逐项对照。
2. **现象**：5V 的 WS2812 接 3.3V GPIO 数据线，灯带不亮或乱闪。**原因**：数据电平不够。**解决**：数据线串 330Ω 后按需加电平转换，或选 3.3V 兼容灯带；5V 与 3.3V 必须共地。
3. **现象**：功放一接喇叭就爆音/自激。**原因**：面包板地线太长、电源去耦不够。**解决**：功放电源脚就近加 10µF+0.1µF，喇叭先断开排查；面包板地线用粗跳线。
4. **现象**：麦克风采到满屏噪声。**原因**：I2S 接线顺序错（SCK/WS/SD 对调）、或模拟地与数字地混在一起。**解决**：对照数据手册核对 SCK/WS/SD；面包板上模拟地单点接开发板 GND。
5. **现象**：测电流时万用表读数跳变、数值离谱。**原因**：表笔接错位置（应串联在电源线上，不是并联）。**解决**：电流档必须串联；不会用就改用 USB 电流表。
6. **现象**：面包板线材接触不良，外设时好时坏。**原因**：跳线松、面包板老化。**解决**：换新跳线；每个外设的 GND 用单独一跳线接开发板 GND（不要共用一根）。
7. **现象**：开发板上一插外设就重启。**原因**：外设峰值电流超过开发板 USB 供电能力，或短路。**解决**：外设电源与开发板分开供（面包板电源轨独立供电），共地即可；检查有无短路。
8. **现象**：急着画板没做原型，打样回来才发现引脚冲突/电源不够。**原因**：跳过 03a。**解决**：回到 03a 补齐验证；本环节的「通过标准」要求每个核心外设都有实测记录。
