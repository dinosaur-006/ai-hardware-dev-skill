## 已学课程要点

### 第 1 课：方向与定位——先让 AI 读懂手里的开发板

- **核心立场**：AI 没有让硬件自动变简单，但改变了做硬件的起点。第一版先不画板、不焊板；先准备一块能上电运行的开发板和说明它的资料，让 AI 先读懂硬件，再从一个清楚的功能开始。
- **判断要不要做成硬件**：先问"这个需求为什么不能只靠软件？硬件的价值怎样在现实现场发生？"——硬件承担实时输入/输出、物理反馈、专属场景。
- **开工四环节（前一个的输出是后一个的输入）**：
  1. 整理硬件资源：把开发板实物与版本、原理图、PCB 正反面、GPIO 引脚表四类资料整理到一起，名称与实物逐项对上。
  2. 搭开发环境：让 AI 结合硬件资料、现有工程和本机，判断复用/修复/安装哪套环境，**人确认后再执行**；基线工程能在本机真实构建通过才算数。
  3. 对齐项目上下文：让编程 Agent 通读硬件资料、环境记录、现有工程并用自己的话完整复述，人逐项纠正；说错或把未知当已知就重来。
  4. 选工程起点开始最小开发：有可运行基线就改基线，没有就从已验证模板新建；先交最小方案（系统边界/实施顺序/验证与回退），人确认后再动代码。
- **项目文件夹结构建议**：`hardware/`（硬件资料）+ `firmware/`（跑通过的固件）+ `README.md`（板名版本、环境基线、起点功能、待确认项标"待确认"）。
- **验收方式**：不是代码或架构图，而是"AI 复述经人核对无误的项目理解" + "同一份基线工程在本机构建通过" + "最小功能构建、写入、真机检查给出可判断结果"。

### 第 2 课：12 步从零烧录跑通（Host Action v1：按键打开应用）

12 步分四段：01–03 读懂与基线（不改代码，先证明工程/环境原本正常）；04–06 协议与实现（核对冻结的 Host Action v1，把动作接进八个实体键）；07–09 通道与构建（有线 USB/无线 BLE 共享同一动作但不能双发）；10–12 写入与验证（先查改动范围，再让真机和 App 给证据）。

关键操作要点：
- **01 只读**：让 AI 读 AGENTS.md / README / flow 记录，用 `easyinput-board-cy` 核对板型与安全边界，全程只读不改。
- **02 基线**：先跑全部宿主测试 + 默认构建，留下"原项目本来正常"的参照；测试数以本轮 CTest 实际发现数为准，不凑数。
- **协议冻结点**：`host_action_v1: true`；固件不存应用路径/UUID，真实 "UUID→应用" 只存在 App 本地，固件只收到 `host_action:<UUID>` 按键配置；BLE 状态不超过 512 字节；v1 字段冻结，未来不兼容改动必须用新版本号。
- **11 烧录**：AI 先显示端口/芯片/完整 MAC/工程版本/产物/烧录命令，停下等人原样输入"确认烧录到 XXXX"才写；不执行 erase_flash，不改分区/偏移/设备身份；自动连接失败时唯一允许的实体操作是"保持开机，短按并松开一次 BOOT"，只重试一次。
- **12 真机验收七项**（每项由人观察，不能推测）：①USB-only 能触发；②BLE-only 能触发；③双连接不双发；④按一次只触发一次；⑤松开不重复；⑥复制/粘贴/快捷键/固定文字仍正常；⑦App 实际打开所选目标应用。App 需明确显示"配置已保存/同步已确认"才算入口成立。
- **BOOT 操作纪律**：保持开机 → 短按 BOOT 并松开 → 出现下载口再烧；禁止按住 BOOT 上电、禁止 BOOT+RESET；烧完**断电再开机**（否则常停在 download 模式）。

### 第 3 课：EasyInput Beatbox 鼓机复刻 + 改造 BPM

> 本地讲义 `D:\硬件耍耍\Waytoagi\easyinput-beatbox\docs\course\waytoagi-making-process.md` 与飞书第 3 课案例 2 内容一致。

- **成品一句话**：板子守着拍子和声音，电脑只负责看见、改谱、同步。节拍/声音/走拍全部在板端独立完成，断开电脑仍能跑；电脑端（Web Serial）只做 Pattern 编辑、状态显示、叠录。
- **分阶段验收**：
  - P0 安全上电与第一声 click：GPIO8 共享电源按顺序拉起（下游脚先安全锁存→拉高 GPIO8→等 50ms→再初始化灯和 I2S）；RGB 亮一下；喇叭播一声短促 clave 风 click（约 9ms、2–2.5kHz），无爆音。
  - P1 独立节拍器：编码器旋转 ±1 BPM（快转 ±5），短按编码器或 S8 启停；BPM 范围 **60–240，上电默认 120**；4 颗 LED 走四拍 + 1 颗状态灯；在 60/120/240 BPM 下 click 速度、重音位置、灯声同步、调速相位连续都要对，拔电脑也能跑。
  - P2 八键鼓机 + 16 步音序器：S1–S6 对应 Closed/Open HH、Clap、Rim、Kick、Snare（GM 通道 10 音号 42/46/39/37/36/38）；6 轨×16 步，A/B Variation + Fill + Swing(50–75%)。
  - P3 网页联动与叠录：USB Serial 每行一条 JSON，收到 `hello`+`state` 才算 synced；REC 武装后把鼓垫演奏量化写进当前 step，不清空已有格子。
- **时间轴是地基**：节拍位置唯一来自 I2S 音频采样游标（32kHz、128 frame/块=4ms、内部 96 PPQN），禁止用 delay/USB/网页计时器推拍；1 四分音符=96 tick，1 十六分=24 tick，1 小节 4/4=384 tick。
- **改造 BPM（作业明确建议项）**：BPM 由旋转编码器调节（±1/快转±5），范围钳在 60–240，调速时保持当前相位连续不重新起小节；网页也可发 `{"t":"bpm","v":128}` 设置。本地相关文件：`firmware/main/seq/tempo.c`、`firmware/main/seq/clock.h`。
- **验收方式**：`python scripts/check_timing_model.py`（误差≤1 sample）+ 真机 60/120/240 BPM、50/66/75% Swing、约 30 分钟连续运行无明显漂移/爆音/断连。

**模板 2（出自第 1 课·第三步"对齐完整项目上下文"）**

> 请先阅读硬件资料、现有工程和环境记录，不要修改任何文件。请用自己的话完整复述：这是什么开发板，有哪些可用输入与输出；现有工程是为了解决什么问题，已经做到哪一步；工程使用什么框架、版本和目标芯片，怎样构建；哪些事实已经确认，哪些地方仍然没有答案。

**模板 3（出自第 2 课·步骤 01"先让 AI 只读固件项目"）**

> 先不要改代码或烧录。按当前 Maker 工程自己的说明发现并运行全部宿主测试；再使用 esp-idf-cy 读取工程声明的 ESP-IDF 版本和目标，激活或准备匹配环境并执行默认构建。课程基线曾用 5.5.5 验证，但以当前仓库的版本化声明为准，不因本机当前版本不同而跳过检查。返回实际测试清单及发现／执行／通过数量、工程要求与实际使用的版本、构建产物或最早失败证据，并说明工作区是否变化。

**模板 5（出自第 2 课·步骤 11"确认目标板后把固件写进去"）**

> 继续在当前 Maker 工程完成"只读验身 → 人工确认 → 写入 → 正常重启"。先读取最新测试、构建和审计记录；若源码或构建配置在审计后变化，分别返回 REAUDIT_REQUIRED 或 REBUILD_REQUIRED 并停止。使用 esp-idf-cy 读取工程声明的 ESP-IDF 版本、目标和待写入产物，使用 easyinput-board-cy 核对 EasyInput V2.0 身份与 BOOT 规则。只读扫描候选端口并确认 ESP32-S3 和 MAC；多设备、芯片不符或身份不清时停止，不猜端口。确认后先显示写入授权卡：端口、芯片、完整 MAC、工程版本／目标、产物和烧录命令；完整 MAC 只在当前对话显示，项目记录仅保留后四位。等待我原样输入"确认烧录到 XXXX"，未收到精确确认前不得写入。确认后重验同一 MAC，再按项目正常流程用显式端口烧录，不执行 erase_flash，不改分区、偏移或设备身份。自动连接失败时，唯一允许的实体操作是"保持开发板开机，短按并松开一次 BOOT"，随后只重试一次；不要按住上电，也不要使用 RESET。写入成功后提示我用板上开关完全关机，再不按 BOOT 正常开机；只做一次不写设备的 USB HID／BLE／App 可见性观察，未看到时记为 UNKNOWN，不重新烧录。用 project-flow-cy 遮罩记录过程，分别返回 DEVICE_CONFIRMED、FLASH_WRITTEN、NORMAL_POWER_CYCLE_CONFIRMED、POST_FLASH_READY 和 FUNCTION_VERIFIED；本步前三项必须为 YES，FUNCTION_VERIFIED 保持 NO。

**模板 6（出自第 2 课·步骤 12"按下按键确认应用真的打开"）**
